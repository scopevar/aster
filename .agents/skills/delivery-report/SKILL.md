# 提测与交付报告

使用固定的 [HTML 模板](assets/report-template.html)，填写 JSON 后生成单文件报告。模板已内嵌 Fumadocs 官方组件、样式和字体；日常生成只需要 Python 3.10+，无需安装依赖、修改 TSX 或构建前端。

## 工作边界

- 本 Skill 负责整理和展示已有事实，不依赖项目名称、框架、Git、目录约定或其他 Skill，也不自行启动测试、代码审查、提交或发布流程。
- 用户要求完整交付时，依照当前任务约定完成开发、验证和必要审查，再生成最终报告。开发期间也可生成草稿；缺少审查记录时写“未提供”或“未执行”，不能写“通过”或“无问题”。
- 结果须对应实际版本；没有提交号可用版本号、构建标识或说明版本信息缺失。分开记录自动化测试、视觉核对、代码审查和用户验收，报告生成不代表验收通过。
- 仅使用真实证据。区分失败、未执行与不适用，以及截图已保存和已人工核对；不能补造命令、输出、截图或审查结论。

## 内容结构

默认六章；根据任务规模合并或删减不适用章节，保留重要缺口。每章先给结论，再放必要证据；长日志放折叠代码块，不堆砌重复信息。

| 章节       | 回答的问题                                             |
| ---------- | ------------------------------------------------------ |
| 交付概览   | 改了什么、为什么、当前结论、对应版本及待决定事项       |
| 需求与改动 | 需求覆盖、关键修改、兼容影响及必要操作                 |
| 测试验证   | 实际命令和结果、失败与未执行项、视觉核对范围           |
| 代码审查   | 审查范围、版本、发现、处理结果和缺口，或缺少记录的说明 |
| 演示与验收 | 操作入口、步骤、预期与实际结果，以及可直接查看的证据   |
| 风险与交付 | 已知限制、交付状态、用户验收状态与后续事项             |

UI 任务优先真实截图或录屏，CLI/API 用输入与实际输出，文档用关键 diff。采用与任务有关的证据，不机械填满每种材料。

## 生成与交付

1. 阅读 [填写与生成指南](references/rendering.md)，把 [example.json](assets/example.json) 复制到任务的输出位置，替换样例内容。
2. 按 [数据与组件约定](references/components.md) 填写章节、表格、折叠日志等内容。数据与模板分开；日常报告不修改 Skill 资产。
3. 执行 `python <Skill目录>/scripts/render.py <报告.json> <报告.html>`。输出是单个 HTML，组件无需网络；图片使用内嵌数据，附件链接另行保持可用。
4. 在浏览器实际打开结果，检查本次涉及的章节、导航、交互和布局。提供 HTML 链接，简要报告结论和重要缺口；未完成的核对如实说明。

保持章节导航。单份报告默认不增加报告选择器、搜索框或“最后更新”字段。模板维护说明见生成指南。
