# 独立代码审查

- 首审使用不继承实现会话的独立 subagent，默认只读；提供原始需求、已确认约束、基线、待审提交、验证结果及缺口，不提供实现推理记录。
- 明确提交范围；先读 diff，再按疑点检查上下游源码和测试。允许必要的针对性验证，不默认重复全量测试，不修改代码或发布。
- 只报告值得处理且有依据的问题：位置、触发条件、实际影响、证据和等级；区分已确认缺陷与待验证疑点，不凑数量。
- P0：严重数据损失、凭据泄露或安全边界失效；P1：核心功能故障或明显兼容性破坏。未解决的 P0/P1 阻断交付。
- P2：有明确影响的非核心缺陷，默认修复，延期交用户决定；P3：轻微问题和改进建议，不阻断，不因此增加复核轮次。定级必须有依据，实现者不得静默忽略或降级。
- 实现者逐项记录“已修复”“经证据排除”或“用户接受延期”。同一问题双方各给一次证据，仍有分歧交用户判断。
- 默认一轮完整审查、一轮修复复核；同一 reviewer 仅复核原 findings、修复 diff 和直接影响范围。即使无 findings，也核对最终提交仍是已审版本。
- 两轮后仍有阻断项或必要验证缺口，报告剩余问题及继续原因，由用户决定。不得更换 reviewer 刷通过，预算耗尽、上下文不足或审查中断只能标记未完成。
- 报告审查基线与提交、轮次、findings 及处理结果、验证缺口，给出“通过／阻断／未完成”。审查通过不代替测试或用户验收。
