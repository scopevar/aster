# 测试规则

新增或修改测试前，先明确以下四点；可在测试注释或完成说明中简要记录，无须重复填写固定表格：

1. **契约**：测试保护哪个用户可见行为、协议、存储不变式或安全边界？
2. **失败场景**：什么可信缺陷会使断言失败？修复问题时对应原缺陷；新增功能时说明不满足验收的场景，不虚构旧版故障。
3. **缺口**：现有测试为什么不够？如果已有同层测试，扩展它而不是复制。工具函数、mock 返回值和源码文本搜索不算独立契约。
4. **边界**：是否在负责该行为的真实模块或系统边界执行？mock 可控制外部依赖和故障，但不能代替被验证的行为；UI 测试应操作真实组件，后端集成测试应经过对应的服务边界。

编写要求：

- 回归测试必须在原缺陷上失败；无法提供旧版本失败证据时，在完成报告中说明原因。
- 视觉回归应检查受影响的布局和交互结果，例如展开前后的位置、滚动范围和焦点，不能只断言文字可见。
- 断言行为结果，不断言调用形状、私有实现或测试自己生成的期望值。
- 一个回归由一个最强边界的 owner 测试覆盖，不在每层重复回放。
- 新增测试须说明已有覆盖的缺口；简单文案、样式或实现调整优先复用已有测试，不以新增文件或用例数量作为完成标准。清理时区分删除无效断言、合并重复场景、迁移层级与降低执行频率，记录保留契约的 owner。
- 主题和窗口尺寸矩阵专注受影响的视觉布局；保存、校验和错误反馈等业务流程验证一次，不在每个视觉组合中重复执行与该组合无关的流程。
- Node 基础层 `unit` 不依赖构建产物、数据库、网络服务或真实进程；普通集成层 `integration` 覆盖这些依赖，外部环境用例保留在 `environment`。`core` 是基础与普通集成的并集。新文件未明确归入基础或环境层时默认进入集成层；分组由 `scripts/test.mjs` 维护，不凭文件名猜测运行依赖。
- Node 测试应能用 `node --import tsx --test <file>` 单独运行；需要构建或环境时沿用 `scripts/test.mjs` 的分组。E2E 测试沿用 Playwright，通过文件名和项目选择相关用例。
- E2E 只验证 Node 测试覆盖不到的内容：真实进程、窗口、系统能力、凭证、跨设备，以及少数跨层主流程。业务语义、幂等、恢复和竞态由 Node 测试负责，不在界面层重放；不为低概率故障逐个注入，不断言具体颜色、像素或类名，截图只留排查需要的。新增 E2E 前先确认对应 Node 测试无法覆盖。
- 界面用例写在 `tests/renderer/`，数据经 `renderer.store()` 写入真实 Store，Main 的其他回答在 `open({ handlers })` 中按契约提供，不在单个用例里手写服务器、打包或桥接；用例结束时 `renderer.unhandled` 应为空。
- 等待具体的界面状态、请求或事件，不用 sleep、固定时长或短超时作为就绪探测；改变状态的操作只执行一次再断言结果，只重试幂等的就绪检查。
- 测试必须清理自己创建的临时目录、端口、进程和监听器。
- 测试产物统一放在 `.runtime/test-results/` 下，不在仓库根目录创建 `test-results-*`。E2E 截图和附件使用 `test.info().outputPath(...)`；自定义 `--output` 也必须位于该父目录内。
- 删除或弱化断言前先确认对应契约已有其他 owner 覆盖。
- 当前仓库没有覆盖率阈值；不要用提高测试数量代替真实行为证明。
- 按根目录 `AGENTS.md` 选择验证范围；明确区分组件测试、集成测试和真实外部服务的验证结果。
